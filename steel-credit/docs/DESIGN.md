# 企业信用评级与风险预警系统 — 详细设计文档

## 一、业务背景

### 1.1 平台现状

本系统服务于一个钢铁行业 B2B 交易平台，平台核心功能和业务约束如下：

| 项目 | 现状 |
|------|------|
| 核心功能 | 询报价撮合（非交易平台） |
| 交易方式 | 全部线下完成 |
| 保证金 | 无 |
| ERP 对接 | 部分商家已对接，可获取其客户的提货/付款数据 |
| 企查查 | 可对接，获取企业风险与关联方信息 |

### 1.2 核心痛点

- **卖家视角**：不了解买家付款信用，无法判断是否赊销；买家频繁取消订单、部分提货、超期欠款无代价
- **买家视角**：不了解卖家交货质量和诚信度，担心货不对版、延迟交付
- **平台视角**：缺乏信用基础设施，难以提升平台交易信任度和粘性

### 1.3 核心设计约束

> **信用评级与风险预警是两套完全独立的体系，必须严格分离。**

- 信用评级：基于平台行为 + ERP 履约数据 + 合作方评价，反映交易信用
- 风险预警：基于企查查公开信息，揭示潜在法律/经营/财务风险
- 一家企业可以信用等级 AAA 但同时有风险预警（如股东涉诉），二者不互相影响

## 二、买卖双角色分立评级

### 2.1 为什么必须分开

钢铁行业中，很多企业（尤其贸易商）既是买家也是卖家。一个企业可能：

- 作为卖家信用极好（交货及时、质量稳定）
- 但作为买家信用较差（经常拖欠上游货款）

如果合并为一个信用评级，会导致买家维度的差表现被卖家维度的好表现稀释，卖家在决定是否赊货时无法获得准确参考。

### 2.2 角色判定

```
企业在平台上发布库存/接受询价/报价 → 卖家角色
企业在平台上发起询价            → 买家角色
两者都有                      → 双角色（同时拥有两张信用画像）
```

### 2.3 企业主页展示

双角色企业在主页上以 Tab 形式展示两张信用画像，并在下方独立展示风险预警信息。三者空间分隔、色系区分，避免混淆。

## 三、买家信用评分模型

### 3.1 评分维度总览

买家信用的核心关注点是**付款是否靠谱、订单是否稳定、提货是否配合**。

#### 全量模式权重分配（满分1000分）

| 维度 | 编码 | 数据来源 | 权重 | 满分 |
|------|------|----------|------|------|
| 企业基础实力 | BASIC | 平台 | 6% | 60 |
| 采购活跃度 | ACTIVITY | 平台 | 6% | 60 |
| 采购行为质量 | BEHAVIOR | 平台 | 6% | 60 |
| 合作关系持续性 | RELATION | 平台 | 5% | 50 |
| 订单履约 | ORDER_FULFILL | ERP | 12% | 120 |
| 提货履约 | PICKUP_FULFILL | ERP | 10% | 100 |
| **付款信用** | **PAYMENT** | **ERP** | **28%** | **280** |
| 合作反馈 | FEEDBACK | 反馈 | 12% | 120 |
| 多商家一致性 | CONSISTENCY | ERP | 15% | 150 |

> 付款信用占比最高（28%），直接体现"欠钱不还是卖家最核心的痛点"。

### 3.2 付款信用维度详细设计（280分）

| 子指标 | 分值 | 评分规则 |
|--------|------|----------|
| 付款及时率 | 80 | 账期内付款的比例 × 80 |
| 平均付款周期偏差 | 40 | 偏差0天:40, ≤7天:30, ≤15天:18, ≤30天:8, >30天:0 |
| 超期欠款率 | 50 | 0%:50, <5%:38, 5-15%:22, 15-30%:10, >30%:0 |
| 严重超期次数(>60天) | 60 | 0次:60, 1次:30, 2次:10, ≥3次:0 |
| 当前欠款状态 | 50 | 无欠款:50, 有欠款未超期:35, 超期≤30天:15, 超期>30天:0 |

### 3.3 订单履约维度详细设计（120分）

| 子指标 | 分值 | 评分规则 |
|--------|------|----------|
| 订单取消率 | 50 | 0%:50, <5%:40, 5-10%:28, 10-20%:15, >20%:0 |
| 部分提货率 | 40 | 0%:40, <10%:30, 10-20%:18, >20%:5 |
| 取消时点合理性 | 30 | 备货前取消:扣分少, 备货后取消:严重扣分 |

### 3.4 欠款行为分级标记

| 等级 | 触发条件 | 展示方式 |
|------|----------|----------|
| 正常 | 无超期 | 无标记 |
| 轻度 | 偶有超期≤15天，已结清 | 无特别标记 |
| 中度 | 超期≥3次/年 或 超期16-60天 | 黄色标记"存在超期付款记录" |
| 严重 | 超期>60天 或 超期金额>应付30% | 橙色标记"存在严重超期" |
| 恶意 | 超期>120天无还款 或 多家投诉 | 红色标记"存在恶意欠款" |

### 3.5 多商家 ERP 一致性加分

当买家出现在 3 家及以上商家的 ERP 中时启用：

- 多商家均无严重超期：+80
- 所有商家均零超期：+40
- 各商家付款表现方差小（稳定一致）：+30

反之，如果在某个商家处有严重超期，取所有商家中的**最差值**，不被平均稀释。

## 四、卖家信用评分模型

### 4.1 评分维度总览

卖家信用的核心关注点是**报价是否诚实、交货是否靠谱、质量是否稳定**。

#### 全量模式权重分配

| 维度 | 编码 | 数据来源 | 权重 |
|------|------|----------|------|
| 企业基础实力 | BASIC | 平台 | 10% |
| 报价服务质量 | QUOTE_SERVICE | 平台 | 15% |
| 供应能力 | SUPPLY | 平台 | 10% |
| 交货履约 | DELIVERY | ERP | 20% |
| 售后与纠纷 | AFTER_SALES | ERP | 10% |
| 合作反馈 | FEEDBACK | 反馈 | 15% |
| 关系持续性 | RELATION | 平台 | 10% |
| 多方一致性 | CONSISTENCY | 综合 | 10% |

## 五、自适应评级模式

### 5.1 模式判定逻辑

```
检查企业是否有 ERP 履约数据（≥3笔）
├── 是 → 全量模式（天花板 AAA，充分度：充分）
└── 否 → 检查合作反馈是否≥5条
         ├── 是 → 平台+反馈模式（天花板 AA，充分度：中等）
         └── 否 → 基础模式（天花板 A，充分度：有限）
```

### 5.2 权重动态调整

无 ERP 数据时，平台行为维度和合作反馈维度的权重自动上调，填补 ERP 维度的空缺。总分始终映射到 1000 分制。

### 5.3 等级天花板

**数据充分度不压低信用等级分数，但限制最终等级的天花板。** 即使基础模式下评分达到 900 分，最终等级也最高为 A。这合理反映了"数据有限条件下的信任边界"。

## 六、风险预警体系

### 6.1 风险分类

| 类别 | 编码 | 具体风险项 |
|------|------|-----------|
| 司法风险 | JUDICIAL | 被执行人、失信被执行人、法院公告、裁判文书 |
| 经营风险 | OPERATIONAL | 行政处罚、经营异常、严重违法 |
| 财务风险 | FINANCIAL | 股权冻结、动产抵押、欠税公告 |
| 变更风险 | CHANGE | 法人变更、注册资本变更、股权变更 |

### 6.2 关联方穿透

| 穿透层级 | 关注对象 |
|----------|----------|
| 第一层 | 控股股东、实际控制人、法定代表人 |
| 第二层 | 股东持股的其他企业 |

### 6.3 独立性保障

| 维度 | 信用评级 | 风险预警 |
|------|---------|---------|
| 数据源 | 平台+ERP+反馈 | 企查查公开信息 |
| API路由 | `/api/credit/**` | `/api/risk/**` |
| 前端色系 | 蓝绿色系 | 橙红色系 |
| 更新频率 | 每日02:00 | 每日03:00 |
| 用户提示 | "基于平台交易数据评定" | "基于公开信息，仅供参考，与信用评级无关" |

## 七、合作印象评价

### 7.1 角色化评价维度

**卖家评买家（侧重付款和履约）：**
- 付款表现（4级）
- 提货表现（4级）
- 订单稳定性（4级）
- 沟通配合度（4级）

**买家评卖家（侧重交货和质量）：**
- 交货及时性（4级）
- 货物品质（4级）
- 报价诚信（4级）
- 沟通配合度（4级）

### 7.2 防刷机制

- 仅有询报价往来记录的双方才能互评
- 同一对企业间评价次数上限 4 次
- 评价可信度权重基于询报价往来次数自动计算（20次以上权重1.0，2次以下权重0.2）
- 反馈数量不足 5 条时不纳入评分

## 八、数据流转

### 8.1 信用评分计算流程

```
定时任务触发（每日02:00）
  │
  ▼
遍历所有企业
  │
  ├── 判定角色（买家/卖家/双角色）
  │
  ├── 买家角色:
  │   ├── 判定评级模式（全量/平台+反馈/基础）
  │   ├── 各维度独立计算
  │   ├── 加权汇总 → 总分 → 等级映射 → 天花板限制
  │   ├── 与上期对比，等级变化则记录历史
  │   └── 保存评分结果
  │
  └── 卖家角色:
      └── (同上，使用卖家维度和权重)
```

### 8.2 ERP 数据同步流程

```
ERP 系统调用同步接口
  │
  ├── 订单数据 → 计算提货超期标记 → 存入 erp_order_record
  │
  └── 付款数据 → 计算超期天数/严重超期标记 → 存入 erp_payment_record
                   │
                   └── 触发买家欠款标记更新
                        → 汇总所有商家的超期数据
                        → 判定欠款等级（正常~恶意）
                        → 更新 buyer_overdue_tag
```

## 九、前端对接指南

### 9.1 企业主页

调用 `GET /api/credit/card/{id}` 获取信用名片，包含：
- `buyerCredit` — 买家信用概要（等级、分数、充分度、核心指标、欠款标记）
- `sellerCredit` — 卖家信用概要
- `riskSummary` — 风险预警概况

三者使用独立的卡片组件展示，信用用蓝绿色系，风险用橙红色系。

### 9.2 询报价列表

调用 `POST /api/credit/badges` 批量获取信用角标，每个企业显示：
- 信用等级角标
- 数据充分度（方块指示器）
- 风险等级图标
- 欠款标记（仅买家）

### 9.3 卖家收到询价时

在询价详情中嵌入询价方的买家信用摘要，重点展示：
- 付款信用维度得分及百分比
- 订单履约/提货履约
- 欠款标记
- 风险预警状态

### 9.4 信用详情页

调用 `GET /api/credit/buyer/detail/{id}` 或 `seller/detail/{id}`，展示：
- 各维度雷达图（ECharts）
- 信用趋势折线图
- 维度得分表格
- 合作方评价摘要
- 数据充分度说明
- 缺失数据提示与建议
